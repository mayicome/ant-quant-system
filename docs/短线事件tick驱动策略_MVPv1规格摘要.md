# 短线事件‑tick 驱动策略 MVP‑v1 规格摘要（修订补全版）

> 
> 定位：A 股 1‑5 交易日短线纯多头研究回测框架，回测验证通过后可迁移实盘；严格对齐 T+1、涨跌停、滑点、交易成本模拟。
> 核心原则
> 
> 
> 1. 不做全市场个股收益率预测，依靠量价事件识别候选标的。
> 2. 无全局总仓位控制器，不做大盘整体开关。
> 3. 第 2‑3 层仅处理**新开仓候选**；只有第 4 层负责管理已经持有的持仓。
> 4. 新增特征必须设置对照组，禁止主观硬规则；**板块强弱打分 / 过滤功能放到 v2 迭代；第 3 层仅使用静态行业归属做持仓数量上限风控，不做强弱判断**。
> 5. 回测粒度：支持 tick / 分钟 bar 降级回放；禁止简单只用日频收盘价回测。

## 整体数据流（MVP‑v1）

> 
> 第 1 层板块环境层 MVP‑v1 暂不编码实现

```
【第2层 候选池+事件识别层（日频收盘粗筛）】
        ↓
【第3层 多维度入场过滤层（模式0，关闭板块强弱逻辑，tick驱动）】
        ↓
【第4层 持仓生命周期引擎（tick/分钟bar内核 + 每日收盘兜底巡检）】
```

## 第 1 层 板块环境层（MVP‑v1：暂不实现，V2 迭代项）

### 用途（未来版本）

输入：行业、概念板块日度 / 盘中数据（涨幅、涨跌比、成交额、相对强度排名）
输出

1. 个股附属特征：主行业强度分位、是否属于强势概念池
2. 账户统计：各行业持仓数量 / 权重

> 
> v2 实现 3 种可切换对照模式
> 
> 
> - 模式 0：关闭板块特征（基线对照组）
> - 模式 1：板块强度仅做候选池内排序加权，不硬剔除标的
> - 模式 2：板块强度硬阈值过滤（对比实验组）

> 
> MVP‑v1 跳过本层，第 3 层**不引用任何板块强弱分数**；仅使用静态行业代码映射做持仓数量上限，属于账户风控，不属于板块强度特征。

## 第 2 层 候选池 + 事件识别层（MVP‑v1 完整实现，补全事件定义）

**执行时机**：每个交易日**收盘后日频执行，每日仅 1 次**；输出的`watch_list`供下一交易日盘中使用。

**输入**

1. 基础股票候选池：沪深主板 / 创业板 / 科创板；剔除北交所、ST/*ST、上市不足 120 交易日、停牌标的。
2. 日线行情数据：不复权收盘价、不复权最低价、成交额、成交量。

**业务逻辑**

1. 执行基础静态池过滤。
2. MVP‑v1 事件：**超跌缩量低吸**，全部条件为可扫描参数，不写死固定值。

> 
> 事件判定（T 日收盘，T 为识别日）
> 
> 
> 1. 回撤计算：`N日回撤 = (close_T / highest(high[T‑N … T‑1]) ) − 1`
>    - 基准取**过去 N 交易日的最高价**（近 N 日高点）；不是 MA20，不是前收盘价；参数扫描 N ∈ [3,5,7]；回撤阈值扫描范围 `-12% ~ -6%`。
> 2. 缩量口径：使用**成交额**（优先，规避股本拆分对成交量干扰）。
>    - `vol_ratio = 当日成交额 / 过去20个交易日日均成交额`；扫描范围 `0.3 ~ 0.7`。
> 3. 可选附加并列条件（**参数开关，可开启 / 关闭做对照实验，不强制必选**）：
>    - cond_a：T 日收阴线（close < open）
>    - cond_b：T 日实体振幅占比阈值
>    - cond_c：T 日价格**不创 N 日新低**
> 
> 
> > 
> > 实现要求：附加条件做成布尔开关；一组实验可以全部关闭附加条件，作为事件基线。

**输出**：`watch_list` 观察池

> 
> 含义：触发超跌缩量事件的股票集合；**进入观察池不等于可以下单**；集合允许为空，为空则下一交易日无新开仓来源。

**边界约束**

- 仅处理潜在新开仓标的，不触碰已有持仓；
- MVP‑v1 暂不实现分歧回调、放量突破事件，留到后续迭代。

## 第 3 层 多维度入场过滤层（MVP‑v1：模式 0，关闭板块强弱逻辑；全部量词量化）

**执行时机**：下一交易日盘中，**跟随 tick / 分钟 bar 流逐根执行**。

**输入**

1. 来自第 2 层：`watch_list`观察池
2. 盘中 tick / 分钟 bar：成交额、价格序列
3. 当前账户持仓列表；**静态行业映射表：all_a_stock_info，取个股主申万行业；不使用东财概念，MVP‑v1 不碰概念**。

**业务逻辑（模式 0）**
对`watch_list`每一只标的逐项校验，全部通过才进入`buy_monitor_set`：

1. **盘中成交额 & 冲击成本保护（量化）**
   - 窗口：**开盘后累计 N 分钟成交额**；N 参数扫描 `20 / 40`；
   - 阈值：开盘后 N 分钟累计成交额 ≥ 800 万；
   - 冲击保护：计划买入金额 ≤ 当前窗口累计成交额的 15%；避免大额订单冲击。
2. **刚结束连续一字跌停复牌过滤（量化）**
   - 判定：连续一字跌停≥2 个交易日；复牌之后**禁止买入 5 个交易日**；到期解除限制。
3. 去重：已经在持仓列表的股票禁止重复开仓。
4. **静态行业持仓数量上限（仅账户风控，无强弱判断）**
   - 数据源：`all_a_stock_info` 主申万行业映射；
   - 参数扫描上限：`3 /4 /5` 只；
   - 逻辑：如果该行业当前持仓已经达到上限，则拒绝该行业新的开仓；**不评估行业涨跌幅、强度，只统计持仓个数**。

**输出**：`buy_monitor_set`待买入监控集合

> 
> 集合内标的才进入 tick 买入监控；集合允许为空，为空当日无新开仓。

**边界约束**

1. 只处理新开仓，不对已有持仓执行卖出、调仓；
2. MVP‑v1**不引入任何行业 / 概念强度分位、板块强弱判断**；行业仅用于持仓数量 cap。

## 第 4 层 持仓生命周期引擎（MVP‑v1 完整实现，系统核心；补全盘中买入触发、现金处理）

> 
> 唯一负责买卖执行与持仓管理模块；**tick / 分钟 bar 级别为主，每日收盘做兜底巡检**。

**输入**

1. 来自第 3 层：`buy_monitor_set`待买入监控集合（用于新开仓）
2. 当前全部持仓列表；每笔持仓独立元数据：
`stock_code、entry_time、entry_price、hold_days_counter、max_profit、max_loss`
3. 实时 tick / 分钟 bar 数据流。

### A 新开仓执行逻辑【补全盘中买入触发条件】

> 
> 买入触发条件（可配置，MVP‑v1 选定：**回踩昨日识别日收盘价附近，市价尽快成交**，作为基线；做成参数可微调区间）

1. 标的处于`buy_monitor_set`；
2. 盘中价格回落到：`[prev_close * (1‑alpha), prev_close * (1+beta)]`
   - `prev_close`：T 识别日（事件触发那天）不复权收盘价；
   - 扫描：`alpha=0.02，beta=0.03`；可网格调整；
3. 满足价格区间条件之后：**下一根可用 bar 以市价发起买入委托，不等待更优限价；尽量尽快成交**。

订单与现金规则（明确：不做权重摊派）

1. 单票最大权重：参数，占账户总净值比例，扫描 5%‑10%。
2. 现金不足处理：
   - 计划下单需要资金 > 当前可用现金：**直接跳过该笔开仓，不缩量降仓买入，也不把资金摊派给其他待买标的**；现金滞留。
3. 涨跌停 & 递延买入：
   - 涨停无法成交 → 标记递延买入；最大递延尝试时长：**一个完整交易日**；超时未成交直接放弃。
4. 成交成功，则生成一条新的持仓对象。

### B 已有持仓管理逻辑

1. **T+1 硬约束**：当日买入的持仓，当日全部 bar 禁止卖出；从下一个交易日 bar 开始才评估卖出条件。
2. bar 级别持续评估卖出条件，满足**任意一条**即触发卖出信号（MVP‑v1 实现前 3 项；信号失效条件 v2 再加）
   - ①固定比例止盈（相对于 entry_price）
   - ②固定比例止损（相对于 entry_price）
   - ③最大持有交易日硬上限（无论盈亏强制卖出，短线核心保护）
3. 卖出信号触发后，下一可用 bar 发起市价卖单；跌停卖不出走递延卖出；最大递延时长 1 个交易日；期满依旧卖不出继续持有，回测如实记录盈亏，**禁止人为抹平损失**。
4. **每日收盘兜底巡检（每日执行 1 次）**
   - 更新全部持仓：持有交易日计数器、最大浮盈、最大浮亏；
   - 处理递延买入 / 卖出队列、更新停牌持仓状态。

**输出**：委托记录、成交记录、更新后的持仓列表。

**边界约束**

1. 无全局统一批量调仓日；买卖由 bar 条件驱动；收盘巡检仅做状态兜底，不会强制批量调仓。
2. 已有持仓不会因为外部市场 / 行业变化被强制清仓；离场只由持仓自身出场条件决定。

## 工程实现约束（新增章节，决定回测可落地）

1. **行情回放范围优化**
   - 不回放全市场全部 tick/bar；**仅回放 `watch_list ∪ 当前全部持仓` 的标的数据**；大幅降低 IO 与内存开销。
2. **回测粒度降级许可**
   - 优先 tick；硬件 / 性能不足时，**允许使用 1 分钟 bar 作为 MVP 降级方案**；禁止使用日频收盘价回测。
3. 价格口径统一
   - 事件计算：不复权日线；
   - 回测撮合、成交、涨跌停判断：全部不复权；
   - 账本 NAV、持仓盈亏：不复权价格。

## 回测运行时序示例（T、T+1 交易日）

1. **T 日收盘（日频）**：执行第 2 层，日线计算事件，输出`watch_list`，供 T+1 盘中使用。
2. **T+1 日盘中（tick / 分钟 bar 循环）**
   - 每一根 bar 到来：执行第 3 层过滤，更新`buy_monitor_set`；
   - 第 4 层：校验待买集合买入价格条件，触发市价买单；对全部持仓评估止盈 / 止损、T+1 约束，生成委托，处理递延。
3. **T+1 日收盘（日频兜底）**：第 4 层执行收盘巡检，更新持仓状态、递延队列。
4. T+1 收盘后，再次运行第 2 层，产出 T+2 的`watch_list`，循环往复。

> 
> ⚠️重要：本策略**不能使用简单日频收盘价回测**，必须 tick / 分钟 bar 回放；否则盘中止盈止损、涨跌停、盘中买点全部失真。

## MVP‑v1 参数扫描范围（全部量化，可网格遍历）

> 
> 使用参数簇评估，不追求单点最优。

1. 超跌缩量低吸事件
   - N 日回撤窗口：[3,5,7]；回撤阈值：‑12% ~ ‑6%
   - 缩量成交额相对 20 日均值：0.3 ~ 0.7
   - 附加条件开关：{全部关闭，开启收阴，开启不创新低，组合开启}
2. 入场过滤参数
   - 开盘后成交额统计窗口分钟：[20,40]；开盘后窗口累计成交额下限：800 万；冲击成本比例上限：15%
   - 一字跌停复牌禁买：连续跌停≥2，复牌后禁买 5 交易日
   - 单行业最大持仓只数：[3,4,5]
3. 盘中买入触发
   - 回踩价格区间 alpha=0.02；beta=0.03
4. 出场参数
   - 止盈比例、止损比例、最大持有交易日
5. 组合风控
   - 单票最大权重占净值：[5%, 10%]；现金不足直接跳过开仓，不缩量、不摊派
6. 交易成本：卖出印花税固定 0.1%；双边（含佣金滑点）敏感性扫描：`0.18% / 0.25%`。

## MVP‑v1 回测输出指标清单

### 组合层面

年化收益、MaxDD、Calmar、Sharpe、年化换手率

### 单笔交易统计（短线重点观测）

总交易笔数、胜率、盈亏比；
止盈出场占比、止损出场占比、最大持有期强制出场占比；
递延买入发生次数、递延卖出发生次数。

> 
> MVP 合格基线：总交易笔数 > 300 笔；优先看**盈亏比**，不追求高胜率；若盈亏比无优势，判定该事件无短线赔率，停止迭代。

## MVP‑v1 明确不实现清单（留给 v2 迭代）

1. 第 1 层板块环境层，板块强度全套逻辑与对照实验组；
2. 持仓「信号失效」卖出条件；
3. 分歧回调事件、放量异动突破事件；
4. 概念板块相关任何逻辑。
